🤔 为什么用 CTE 分步拆解？
首单识别、品类分类、窗口预计算、回访判定、复购统计、Top3 聚合——独立逻辑拆成多个 CTE，每步只用前一步的结果。first_order → first_cate → cust_pay → cust_win → cust_base → cust_visit / cust_repurchase → cust_flag → monthly + top3，像搭积木一样层层递进。

📖 业务术语

术语含义
SKUStock Keeping Unit，单品唯一标识（如 dress_01 = 黑色连衣裙 M 码）
cate_nm商品品类（Category），本题有 women / men / kids / young
回访率首单后 30 天内再次访问的用户占比 = 回访人数 ÷ 新客人数
复购率首单后 30 天内再次下单的用户占比 = 复购人数 ÷ 新客人数

📄 题目描述

SHEIN 运营团队想分析2020年1月起的新客户：按首单品类分成 A/B/C 三组，看各组在首单后 30 天内的回访率和复购率，以及复购最多的 Top3 品类。

📥 t2_order_detail（订单表）
每个用户每次订单一行。user_id + pay_time + cate_nm 是关键字段
📥 t2_user_visit_di（回访日志表）
记录用户每天的访问。dt 是 yyyymmdd 格式字符串

分组规则：

  • A 类：首单只买了 women
  • B 类：首单买了 women + men（恰好这两种）
  • C 类：其他所有情况（women+men+kids / 只 kids / 只 young 等）

📐 图解即思路

① CTE: first_order — ROW_NUMBER 开窗取每个用户最早一笔
WITH ranked AS (
    -- ① 开窗取首单：ROW_NUMBER 分组排序，rn=1 即最早一笔
    SELECT user_id, pay_time, sku, cate_nm, sales_cnt,
           ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY pay_time) AS rn
    FROM t2_order_detail
),
first_order AS (
    SELECT user_id, pay_time AS first_pay,
           DATE_FORMAT(pay_time, '%Y-%m') AS first_month
    FROM ranked WHERE rn = 1
),
② CTE: first_cate — 条件聚合标记每个用户首单买了哪些品类
first_cate AS (
    -- ② 条件聚合：MAX(CASE WHEN) 替代 GROUP_CONCAT，全引擎兼容
    SELECT f.user_id, f.first_month, f.first_pay,
           MAX(CASE WHEN o.cate_nm = 'women' THEN 1 ELSE 0 END) AS has_women,
           MAX(CASE WHEN o.cate_nm = 'men'   THEN 1 ELSE 0 END) AS has_men,
           MAX(CASE WHEN o.cate_nm = 'kids'  THEN 1 ELSE 0 END) AS has_kids
    FROM first_order f
    JOIN ranked o ON f.user_id = o.user_id AND o.rn = 1
    GROUP BY f.user_id, f.first_month, f.first_pay
),
③ CTE: new_cust — 用 CASE 分类 A/B/C，只保留 2020年起
new_cust AS (
    -- CASE 分类 + 过滤 2020年起
    SELECT user_id, first_month,
           CASE WHEN has_women=1 AND has_men=0 AND has_kids=0 THEN 'A'
                WHEN has_women=1 AND has_men=1 AND has_kids=0 THEN 'B'
                ELSE 'C' END AS category
    FROM first_cate WHERE first_month >= '2020-01'
),
④-a CTE: cust_pay → cust_win → cust_base — 窗口边界预计算（各格式一次算出，零重复）
cust_pay AS (
    -- ③a1 只解析一次：字符串 first_pay → datetime pay_dt
    SELECT nc.*, STR_TO_DATE(nc.first_pay, '%Y-%m-%d %H:%i') AS pay_dt
    FROM new_cust nc
),
cust_win AS (
    -- ③a2 只算一次：pay_dt + 30 天 → pay30_dt
    SELECT cp.*, DATE_ADD(cp.pay_dt, INTERVAL 30 DAY) AS pay30_dt
    FROM cust_pay cp
),
cust_base AS (
    -- ③a3 输出边界：按目标格式各格式化一次，无重复表达式
    SELECT cw.*,
           DATE_FORMAT(cw.pay_dt,   '%Y%m%d')         AS visit_start,
           DATE_FORMAT(cw.pay30_dt, '%Y%m%d')         AS visit_end,
           DATE_FORMAT(cw.pay30_dt, '%Y-%m-%d %H:%i') AS repurchase_end
    FROM cust_win cw
),
④-b CTE: cust_visit + cust_repurchase + cust_flag — JOIN 预聚合 + LEFT JOIN 打标
cust_visit AS (
    -- ③b1 30 天内回访：JOIN 窗口 + DISTINCT 压缩到每用户一行
    SELECT DISTINCT cb.user_id
    FROM cust_base cb
    JOIN t2_user_visit_di v
      ON v.user_id = cb.user_id
     AND v.dt BETWEEN cb.visit_start AND cb.visit_end
),
cust_repurchase AS (
    -- ③b2 30 天内复购：JOIN 窗口 + DISTINCT 压缩到每用户一行
    SELECT DISTINCT cb.user_id
    FROM cust_base cb
    JOIN t2_order_detail o2
      ON o2.user_id = cb.user_id
     AND o2.pay_time > cb.first_pay
     AND o2.pay_time <= cb.repurchase_end
),
cust_flag AS (
    -- ③b3 打标：LEFT JOIN 预聚合结果（替代 EXISTS），主查询零膨胀
    SELECT cb.*,
           CASE WHEN cv.user_id IS NOT NULL THEN 1 ELSE 0 END AS has_visit,
           CASE WHEN cr.user_id IS NOT NULL THEN 1 ELSE 0 END AS has_repurchase
    FROM cust_base cb
    LEFT JOIN cust_visit cv      ON cv.user_id = cb.user_id
    LEFT JOIN cust_repurchase cr ON cr.user_id = cb.user_id
),
⑤ CTE: monthly — 按月×品类聚合，回访率 & 复购率
monthly AS (
    -- ④ 聚合：月度 × 品类统计
    SELECT first_month, category,
           COUNT(DISTINCT user_id) AS cust_cnt,
           COUNT(DISTINCT CASE WHEN has_visit      THEN user_id END) AS visit_cnt,
           COUNT(DISTINCT CASE WHEN has_repurchase THEN user_id END) AS repurchase_cnt
    FROM cust_flag GROUP BY first_month, category
),
⑥ top3 + 最终输出 — JOIN monthly + top3，拼接回访率/复购率/复购品类
top3 AS (
    -- ④ 开窗取 Top3 复购品类
    SELECT first_month, category,
           MAX(CASE WHEN rn=1 THEN cate_nm END) AS top1,
           MAX(CASE WHEN rn=2 THEN cate_nm END) AS top2,
           MAX(CASE WHEN rn=3 THEN cate_nm END) AS top3
    FROM (
        SELECT nc.first_month, nc.category, o.cate_nm,
               ROW_NUMBER() OVER (PARTITION BY nc.first_month, nc.category
                                  ORDER BY COUNT(DISTINCT nc.user_id) DESC, o.cate_nm) AS rn
        FROM new_cust nc
        JOIN t2_order_detail o ON o.user_id = nc.user_id
           AND o.pay_time > nc.first_pay
           AND o.pay_time <= DATE_ADD(STR_TO_DATE(nc.first_pay, '%Y-%m-%d %H:%i'), INTERVAL 30 DAY)
        WHERE nc.first_month >= '2020-01'
        GROUP BY nc.first_month, nc.category, o.cate_nm
    ) t WHERE rn <= 3
    GROUP BY first_month, category
)
SELECT m.first_month   AS 首单月份,
       m.category      AS 首单品类,
       m.cust_cnt      AS 新客人数,
       m.visit_cnt     AS 回访人数,
       CONCAT(ROUND(m.visit_cnt*100.0/m.cust_cnt,0),'%') AS 回访率,
       m.repurchase_cnt AS 复购人数,
       CONCAT(ROUND(m.repurchase_cnt*100.0/m.cust_cnt,0),'%') AS 复购率,
       CONCAT_WS(',', t.top1, t.top2, t.top3) AS 复购的top3品类
FROM monthly m LEFT JOIN top3 t
    ON m.first_month = t.first_month AND m.category = t.category
ORDER BY m.first_month, m.category;

⬆ 以上 7 帧的 SQL 按顺序拼接（含 top3 CTE + 最终 SELECT），即为完整答案。

⚠️ 易错点

  • ROW_NUMBER 取首单比 MIN+JOIN 更简洁：一次扫描完成排序，避免 MIN 查到时间后再 JOIN 回来取其他字段
  • 条件聚合代替字符串拼接：MAX(CASE WHEN cate_nm='women' THEN 1 ELSE 0 END) — 不依赖 GROUP_CONCAT（MySQL 专属）或 collect_set（Hive 专属），全引擎通用且天然去重
  • 日期格式统一 + 零重复表达式：pay_time 格式 yyyy-MM-dd HH:mm，visit dt 格式 yyyymmdd — cust_pay→cust_win→cust_base 分层递进，pay_dt/pay30_dt 各只算一次，最后按目标格式各自格式化，避免整坨 DATE_FORMAT(DATE_ADD(STR_TO_DATE(...))) 重复书写
  • 存在性判断用 JOIN 预聚合而非 EXISTS：cust_visit/cust_repurchase 先 JOIN 窗口条件 + DISTINCT 把命中用户压缩成一行，再 LEFT JOIN 打标 — 避免相关子查询逐行执行，主查询也不会因多笔订单/多次访问而笛卡尔膨胀
  • Top3 用 MAX(CASE WHEN rn=N)：比 GROUP_CONCAT 更通用。注意 CONCAT_WS 会自动跳过 NULL（空品类变空串而非 'NULL,NULL'）
  • Hive/Spark 适配：date_format / date_add 替代 MySQL 的 DATE_FORMAT / DATE_ADD；CONCAT 替代 CONCAT_WS 如遇兼容问题

🧪 自我检验

Q1: 如果首单买了 men（只有 men），CASE 会分到哪一类？为什么？

✅ 答：C 类。 CASE 只匹配 'women' 和 'men,women' 两种——只买 men 不匹配任何条件，进 ELSE → C 类。

Q2: 如果需求改为「只看 7 天内回访」，改哪里？

✅ 答： cust_flag 和 top3 的 CTE 中，把 INTERVAL 30 DAY 改成 INTERVAL 7 DAY 即可。
