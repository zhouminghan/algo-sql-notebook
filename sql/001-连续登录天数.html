为什么用窗口函数而不是自连接？
自连接需要把同一用户的每条记录和其他记录比较（O(n²)），而且跨月/跨年边界处理麻烦。row_number() 差值分组法一次扫描即可完成，O(n log n) 搞定。

题目描述

有一张用户登录表 user_login，找出每个用户的最长连续登录天数。同一天多次登录只算一次。

user_login（源数据）
同一天多次登录保留全部记录（DISTINCT 去重回 frame① 处理）

图解即思路

① CTE: dedup — 去重，为 ROW_NUMBER 编号做准备
WITH dedup AS (
    SELECT DISTINCT user_id, login_date FROM user_login
),
② CTE: numbered — ROW_NUMBER 按用户分组、按日期排序编号
numbered AS (
    SELECT user_id, login_date,
           ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) AS rn
    FROM dedup
),
③ CTE: grouped — 日期减去序号，连续日期的差值 grp 相同
grouped AS (
    SELECT user_id, login_date, rn,
           DATE_SUB(login_date, INTERVAL rn DAY) AS grp
    FROM numbered
)
④ 按 grp 分组聚合 — COUNT + MAX 取最长连续天数
SELECT user_id, MAX(consecutive_days) AS max_consecutive_days
FROM (
    SELECT user_id, grp, COUNT(*) AS consecutive_days
    FROM grouped GROUP BY user_id, grp
) t
GROUP BY user_id ORDER BY user_id;

以上 4 帧的 SQL 按顺序拼接，即为完整答案。

GROUP BY user_id ORDER BY user_id;

易错点

  • 必须先 DISTINCT 去重：如果同一天有两条记录，row_number 会让它们有不同编号，差值就不同了，同一天会被算成两天
  • 跨月/跨年没问题：DATE_SUB(login_date, INTERVAL rn DAY) 自动处理月份和年份边界
  • 只有 1 天登录：差值分组后 COUNT=1，正确返回 1

自我检验

Q1: 如果不去重（不用 DISTINCT），测试数据 user_id=4 同一天登录两次，结果会是多少？为什么？

答： 同一天两条记录 row_number 分别为 1 和 2，差值 = 同一天 - 不同序号 → 产生两个不同的 grp 值，这两个 grp 各自只有 1 条记录，COUNT=1。最后 MAX=1——巧合结果对，但内部逻辑是错的。如果有用户连续 2 天且其中一天有重复，就会被切成多个片段，连续天数被低估。

Q2: 题目改为「找出至少连续登录 N 天的用户」（N 可配置），SQL 怎么改？

答： 在最外层查询加 HAVING MAX(consecutive_days) >= N。如果 N 很大（如 100），可以先在 grouped 子查询后用 WHERE 提前过滤，避免对大量不可能满足条件的数据做最终聚合：WHERE consecutive_days >= N 放在内层子查询里即可。
