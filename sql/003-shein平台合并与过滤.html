为什么用 CASE WHEN 合并而不是 UNION + 子查询？
直接在 SELECT 里用 CASE WHEN 把 AMZDE/AMZUK 映射为 AMZEU，单次扫描完成，无需额外 UNION 再 GROUP BY 重聚合。配合 JOIN 过滤 remote=1，逻辑一条线到底。

业务术语

术语含义
market平台编码，如 AMZ=亚马逊美国、AMZDE=亚马逊德国、AMZUK=亚马逊英国、US=美国站、WAL=沃尔玛
SKUStock Keeping Unit，单品唯一标识
remoteshein_B 中的标记位，1=该平台需排除，0=保留
qty销量/库存量

题目描述

SHEIN 机试题。有销售表 shein_A 和平台属性表 shein_B：

  1. 平台合并：AMZDE 和 AMZUK 合并为新的 AMZEU
  2. 过滤：排除 remote = 1 的平台
  3. 输出：不重复的 (market, sku)，且对应 qty ≥ 4
shein_A（销售表）
每行 = 某平台某 SKU 的销量
shein_B（平台属性表）
remote=1 表示该平台需排除

图解即思路

① CTE: merged — CASE WHEN 合并平台 + JOIN 过滤 remote
WITH merged AS (
    -- ① 合并平台名 + JOIN 过滤 remote=1 的平台
    SELECT CASE a.market
             WHEN 'AMZDE' THEN 'AMZEU'
             WHEN 'AMZUK' THEN 'AMZEU'
             ELSE a.market END AS market,
           a.sku, a.qty
    FROM shein_A a
    JOIN shein_B b ON a.market = b.market AND a.sku = b.sku
    WHERE b.remote = 0
),
② 最终输出 — 去重 + qty ≥ 4 过滤
SELECT DISTINCT market, sku, qty
FROM merged
WHERE qty >= 4
ORDER BY market, sku;

以上 2 帧的 SQL 按顺序拼接，即为完整答案。

SQL 代码

WITH merged AS (
    -- ① 合并平台名 + JOIN 过滤 remote=1 的平台
    SELECT CASE a.market
             WHEN 'AMZDE' THEN 'AMZEU'
             WHEN 'AMZUK' THEN 'AMZEU'
             ELSE a.market END AS market,
           a.sku, a.qty
    FROM shein_A a
    JOIN shein_B b ON a.market = b.market AND a.sku = b.sku
    WHERE b.remote = 0
)
SELECT DISTINCT market, sku, qty
FROM merged
WHERE qty >= 4
ORDER BY market, sku;

易错点

  • 合并发生在 JOIN 之前：CASE WHEN 在 SELECT 里，对 shein_A 的原始 market 做映射，映射后与 shein_B JOIN — 但 shein_B 里只有 AMZDE/AMZUK 的原始记录，合并后的 AMZEU 在 shein_B 中不存在。因此 必须用 shein_A 的原始 market 与 shein_B JOIN，再在 SELECT 中做合并。
  • remote=0 不是 remote≠1：题目说"排除 remote=1 的"，所以用 WHERE b.remote = 0。如果 remote 字段有其他值（如 NULL），remote != 1 可能漏掉 NULL，用 = 0 更精确。
  • DISTINCT 去重：合并后 AMZEU 下可能有相同 sku 多条（原 AMZDE+AMZUK 的 qty 各自独立），用 DISTINCT 确保输出不重复。
本地复现（CREATE TABLE + INSERT + SQL） 
CREATE TABLE shein_A (
    market VARCHAR(10), sku VARCHAR(20), qty INT
);
INSERT INTO shein_A VALUES
('AMZ',   'Label-1', 3),
('US',    'Label-2', 2),
('AMZDE', 'Label-3', 4),
('AMZUK', 'Label-3', 2),
('WAL',   'Label-4', 4);

CREATE TABLE shein_B (
    market VARCHAR(10), sku VARCHAR(20), remote INT
);
INSERT INTO shein_B VALUES
('AMZ',  'Label-1', 0),
('US',   'Label-2', 0),
('WAL',  'Label-4', 1);

WITH merged AS (
    SELECT CASE a.market
             WHEN 'AMZDE' THEN 'AMZEU'
             WHEN 'AMZUK' THEN 'AMZEU'
             ELSE a.market END AS market,
           a.sku, a.qty
    FROM shein_A a
    JOIN shein_B b ON a.market = b.market AND a.sku = b.sku
    WHERE b.remote = 0
)
SELECT DISTINCT market, sku, qty
FROM merged
WHERE qty >= 4
ORDER BY market, sku;

自我检验

Q1: 为什么 WAL/Label-4 的 qty=4 但没有出现在结果中？

答： shein_B 中 WAL 的 remote=1，JOIN 时被 WHERE b.remote=0 过滤掉了。

Q2: 如果 AMZDE 和 AMZUK 各自都有 qty ≥ 4 的同 sku，DISTINCT 后结果是什么？

答： 合并后 AMZEU + 同 sku 出现多条，DISTINCT 只保留一行，qty 取哪条取决于数据顺序（题目没要求 SUM，用 DISTINCT 即可）。如果需求是合并后 SUM qty，应改用 GROUP BY market, sku HAVING SUM(qty) >= 4。
