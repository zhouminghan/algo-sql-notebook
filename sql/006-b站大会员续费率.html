为什么用 CTE 分步拆解？
LEAD 补全下一次订阅 → DATEDIFF 判定续费窗口 → 按月 DISTINCT 聚合，三件事独立成块。with_next → renew_flag → 最终聚合，像搭积木一样层层递进，每一步的输出都能单独验证。

业务术语

术语含义
大会员B 站付费会员，本题泛指付费订阅用户
到期用户数end_date 落在该月的去重用户数（分母）
30 天内续费下一条订阅 start_date 与当前 end_date 间隔 ≤ 30 天
续费率30 天内续费用户数 ÷ 到期用户数
LEAD窗口函数，取同分组内「下一条」记录的某列值，本题用于补全下次订阅时间
DATEDIFFMySQL 日期差函数，返回两个日期的天数差

题目描述

B 站大会员业务分析：现有一张订阅表 t7_vip_subscription，记录用户每次订阅的起止时间。请按到期月份统计：到期用户数、30 天内续费用户数、续费率。续费行为复杂：有的当天续、有的拖几周、有的中途改续费方式、有的到期后再也没回来——需要在窗口判定里把这些场景都覆盖到。

t7_vip_subscription（大会员订阅表）
每个用户每次订阅一行；同一用户可有多条订阅记录（续费产生新记录）

图解即思路

① CTE: with_next — LEAD 补全每个用户下一次订阅的开始时间
WITH with_next AS (
    -- ① 用 LEAD 补全每个用户下一次订阅的开始时间
    SELECT user_id, start_date, end_date,
           SUBSTR(end_date, 1, 7) AS expire_month,
           LEAD(start_date) OVER (PARTITION BY user_id ORDER BY start_date) AS next_start
    FROM t7_vip_subscription
),
② CTE: renew_flag — 计算续费间隔，标记是否 30 天内续费
renew_flag AS (
    -- ② 计算续费间隔，标记是否 30 天内续费
    SELECT user_id, expire_month,
           DATEDIFF(next_start, end_date) AS gap_days,
           CASE WHEN DATEDIFF(next_start, end_date) <= 30 THEN 1 ELSE 0 END AS is_renew
    FROM with_next
)
③ 最终聚合 — 按月 DISTINCT 统计到期 / 续费人数与续费率
-- ③ 按月聚合：到期人数 / 续费人数 / 续费率
SELECT expire_month AS 到期月份,
       COUNT(DISTINCT user_id) AS 到期用户数,
       COUNT(DISTINCT CASE WHEN is_renew = 1 THEN user_id END) AS 续费用户数,
       ROUND(COUNT(DISTINCT CASE WHEN is_renew = 1 THEN user_id END) / COUNT(DISTINCT user_id), 4) AS 续费率
FROM renew_flag
GROUP BY expire_month
ORDER BY expire_month;

以上 3 帧的 SQL 按顺序拼接（两个 CTE + 最终 SELECT），即为完整答案。

SQL 代码

WITH with_next AS (
    -- ① 用 LEAD 补全每个用户下一次订阅的开始时间
    SELECT user_id, start_date, end_date,
           SUBSTR(end_date, 1, 7) AS expire_month,
           LEAD(start_date) OVER (PARTITION BY user_id ORDER BY start_date) AS next_start
    FROM t7_vip_subscription
),
renew_flag AS (
    -- ② 计算续费间隔，标记是否 30 天内续费
    SELECT user_id, expire_month,
           DATEDIFF(next_start, end_date) AS gap_days,
           CASE WHEN DATEDIFF(next_start, end_date) <= 30 THEN 1 ELSE 0 END AS is_renew
    FROM with_next
)
-- ③ 按月聚合：到期人数 / 续费人数 / 续费率
SELECT expire_month AS 到期月份,
       COUNT(DISTINCT user_id) AS 到期用户数,
       COUNT(DISTINCT CASE WHEN is_renew = 1 THEN user_id END) AS 续费用户数,
       ROUND(COUNT(DISTINCT CASE WHEN is_renew = 1 THEN user_id END) / COUNT(DISTINCT user_id), 4) AS 续费率
FROM renew_flag
GROUP BY expire_month
ORDER BY expire_month;

易错点

  • COUNT(DISTINCT user_id) 不能省：同一用户可能有多条订阅记录（不同月份各有一条到期），COUNT(*) 会重复计数。这里 DISTINCT 确保每月内同一用户只算一人
  • DATEDIFF 结果可能是 0 或负数：当天续费（u04 首尾相接）间隔为 0，提前续费甚至为负。<= 30 会把当天续和提前续都算作「30 天内」；若业务只想统计「到期后 30 天」，改成 DATEDIFF(next_start, end_date) BETWEEN 0 AND 30
  • 最后一条记录的 next_start 为 NULL：LEAD 没有「下一条」，DATEDIFF(NULL, end_date) 结果为 NULL，CASE 条件不成立 → 不计入续费人数，但仍计入到期人数分母。这是正确的（无法判断最后一条是否续费），但会把续费率整体拉低；业务上可加 WHERE next_start IS NOT NULL 只统计「有机会续费」的记录，需权衡
  • LEAD 必须按 start_date 排序：ORDER BY start_date 保证「下一条」是时间上的下一次订阅；漏排会导致 next_start 取值错乱
  • 按月截断的写法：字符串日期用 SUBSTR(end_date, 1, 7)；若列是 DATE 类型，MySQL 用 DATE_FORMAT(end_date, '%Y-%m')，Hive/Spark 用 substr(date_format(end_date,'yyyy-MM-dd'),1,7) 或 date_format

举一反三

  • 按订阅时长分析续费率：先算 DATEDIFF(end_date, start_date) 分月卡/季卡/年卡，再看各时长的续费率差异——年卡用户续费率通常更高，指导月卡用户升档
  • 续费间隔分布（续费漏斗）：把 DATEDIFF(next_start, end_date) 分段——0 天(立即续) / 1-7 天(快速续) / 8-30 天(正常续) / 31-90 天(回流) / >90 天或未续(流失)
  • 最长连续续费月数：用 LEAD 链式追踪「每次续费间隔 ≤ 30 天」的连续段，识别连续续费 12 个月以上的超级会员——本质是「最长连续登录」问题的变体

自我检验

Q1: 为什么续费人数用 COUNT(DISTINCT CASE WHEN is_renew = 1 THEN user_id END) 而不是 COUNT(*) WHERE is_renew = 1？

答： 防御同一用户同月多条到期记录被重复计数——DISTINCT 保证每月内同一用户只算一人，这也是「按月分组 + 同一用户多订阅周期」场景的标准写法。

Q2: u07 在 2024-01 的续费间隔是多少？为什么计入续费？

答：9 天。 2024-01-01 到期、2024-01-10 开始下一条订阅（跨年），DATEDIFF = 9 ≤ 30，所以计入 2024-01 的续费人数，该月续费率 100%（样本量仅 1，注意可信度）。

Q3: 如果只想统计「到期后 30 天内续费」（不含当天/提前），怎么改？

答： 把判定条件改成 DATEDIFF(next_start, end_date) BETWEEN 1 AND 30（或 BETWEEN 0 AND 30，视当天续是否算「到期后」的业务口径而定）。
