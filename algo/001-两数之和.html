🤔 为什么用哈希表？
暴力双循环 O(n²)，10⁴ 数据量能过但不够优雅。哈希表把「查找目标值」从 O(n) 降到 O(1)，一边遍历一边查，一次过。

📄 题目描述

给定一个整数数组 nums 和一个整数目标值 target，请你在该数组中找出 和为目标值 target 的那 两个 整数，并返回它们的数组下标。

你可以假设每种输入只会对应一个答案，并且你不能使用两次相同的元素。

示例：

输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：因为 nums[0] + nums[1] == 9 ，返回 [0, 1]

📐 图解即思路

🗺️ HashMap 说明
Key = 数组元素值（用来快速查找 complement 是否存在）
Value = 数组下标（命中后直接获取对方的 index）
算法：遍历数组 → 算 complement → 查 HashMap → 命中则返回，否则存入继续
① i=0，nums[0]=2
② i=1，nums[1]=7
③ i=2，nums[2]=11（如未命中则继续）
④ i=3，nums[3]=15（如未命中则继续）
✅ 结论
i=1 时 nums[0] + nums[1] = 2 + 7 = 9，返回 [0, 1]。
关键：先查 complement 再存当前值，避免同一个元素被用两次。
一次遍历 O(n)，HashMap 查找 O(1)，空间 O(n)。

📝 最优解代码

Python

def twoSum(nums, target):
    seen = {}  # val -> index
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i
    return []

Java

public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> map = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (map.containsKey(complement)) {
            return new int[]{map.get(complement), i};
        }
        map.put(nums[i], i);
    }
    return new int[]{};
}

⏱ 复杂度分析

  • 时间：O(n) — 一次遍历，哈希表查找 O(1)
  • 空间：O(n) — 最坏情况存储全部 n 个元素

⚠️ 易错点

  • 不能先存再查：先 seen[num]=i 再查 complement，同一个元素可能被用两次（如 target=6, nums=[3,2,4]，3+3=6 就会错误返回 [0,0]）
  • 哈希冲突：Java HashMap 底层链表长度 >8 会转红黑树，但在两数之和场景下不会触发
🧪 自我检验

Q1: 如果 nums 有重复元素（如 [3,3]），解法还正确吗？为什么？

✅ 答：正确的。 顺序是先查 complement 再存 seen。i=0 时 seen 为空，查不到 3；存入 (3,0)。i=1 时查 complement=3，在 seen 中找到 (3,0) → 返回 [0,1]。如果先存再查，第一次就查到同一个元素 3 了，返回 [0,0] 错误。

Q2: 题目改为「返回所有两数之和等于 target 的不重复配对」，怎么改？

✅ 答：用排序 + 双指针。先排序，左指针从 0 开始，右指针从末尾开始。和 < target 左指针右移，和 > target 右指针左移，相等则收集一对然后两个指针都跳过重复值。或者仍用哈希表但用 Set 来去重配对结果。
