两数相加

中等 链表 数学
→ LeetCode 原题
🤔 为什么用链表模拟加法？
两个链表都是逆序存储（头节点是个位），天然符合竖式加法从低位到高位的计算顺序。只需同步遍历两条链表，逐位相加并处理进位，就像在纸上做加法一样。时间复杂度 O(max(m, n))，空间复杂度 O(max(m, n))（结果链表）。

📄 题目描述

给你两个 非空 的链表，表示两个非负的整数。它们每位数字都是按照 逆序 的方式存储的，并且每个节点只能存储 一位 数字。

请你将两个数相加，并以相同形式返回一个表示和的链表。

你可以假设除了数字 0 之外，这两个数都不会以 0 开头。

示例：

输入：l1 = [2,4,3], l2 = [5,6,4]
输出：[7,0,8]
解释：342 + 465 = 807
即逆序链表：2→4→3 表示 342，5→6→4 表示 465，和 7→0→8 表示 807

📐 图解即思路

🔗 竖式加法模拟
初始化 dummy 头节点 → 同步遍历 l1 和 l2 → 逐位求和 sum = x + y + carry → 新节点存 sum % 10 → 进位 carry = sum / 10 → 如果最终还有进位，补一个节点。
① 初始状态：l1 = 2→4→3，l2 = 5→6→4，carry = 0
② 个位：2 + 5 + 0 = 7，结果节点 7，carry = 0
③ 十位：4 + 6 + 0 = 10，结果节点 0，carry = 1
④ 百位：3 + 4 + 1 = 8，结果节点 8，carry = 0
⑤ 遍历结束，carry = 0，最终结果：7→0→8
✅ 结论
2→4→3（342）+ 5→6→4（465）= 7→0→8（807）。
关键：进位要带到下一位，即使一条链表已遍历完也要继续处理进位。最后如果 carry = 1 需要额外加一个节点。

📝 最优解代码

Python

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def addTwoNumbers(l1, l2):
    dummy = ListNode(0)
    curr = dummy
    carry = 0

    while l1 or l2 or carry:
        x = l1.val if l1 else 0
        y = l2.val if l2 else 0
        total = x + y + carry
        carry = total // 10
        curr.next = ListNode(total % 10)
        curr = curr.next
        if l1: l1 = l1.next
        if l2: l2 = l2.next

    return dummy.next

Java

public ListNode addTwoNumbers(ListNode l1, ListNode l2) {
    ListNode dummy = new ListNode(0);
    ListNode curr = dummy;
    int carry = 0;

    while (l1 != null || l2 != null || carry != 0) {
        int x = (l1 != null) ? l1.val : 0;
        int y = (l2 != null) ? l2.val : 0;
        int sum = x + y + carry;
        carry = sum / 10;
        curr.next = new ListNode(sum % 10);
        curr = curr.next;
        if (l1 != null) l1 = l1.next;
        if (l2 != null) l2 = l2.next;
    }

    return dummy.next;
}

⏱ 复杂度分析

  • 时间：O(max(m, n)) — 遍历较长的那条链表一次
  • 空间：O(max(m, n)) — 结果链表长度（不算输入占用的空间则为 O(1)，因为只用了常数个临时变量）

⚠️ 易错点

  • 忘记最后的进位：如 5 + 5 = 10，遍历结束后 carry = 1 需要追加一个值为 1 的节点，否则结果少一位
  • 循环条件不完整：必须 while l1 or l2 or carry，如果只写 while l1 and l2 会在不等长链表时丢失剩余节点
  • dummy 头节点：使用 dummy 简化边界处理，最后返回 dummy.next 而非 dummy
🧪 自我检验

Q1: 如果 l1 = [9,9,9,9,9,9,9]，l2 = [9,9,9,9]（即 9999999 + 9999），结果链表的长度是多少？

✅ 答：8 个节点。 9999999 + 9999 = 10009998，结果是 8 位数，比最长输入（7位）多 1。每连续进位一次就多一个节点，极端情况下会一直进位到最高位产生一个新节点。所以循环条件必须包含 carry != 0。

Q2: 如果不创建新链表，直接在 l1 上就地修改可行吗？有什么风险？

✅ 答：可以，但有风险。 如果 l1 比 l2 短，需要把 l2 的剩余部分接到 l1 后面，或者 l1 用完时切到 l2。如果最后有额外进位，还得新建节点。就地修改代码复杂且容易出错，面试中创建新链表更清晰安全。空间复杂度仍然是 O(max(m,n)) 因为结果链表本身就占用这么多空间。
